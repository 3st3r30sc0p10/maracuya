==================================================
TRI-STATE CLASSIFICATION (CORE LOGIC)
==================================================

Implement in tri_state.py.

Inputs:

- s0, s1 ∈ [0,1]
- k # margin
- amb_min_max # evidence gate

Compute:

- delta = abs(s0 - s1)
- max_score = max(s0, s1)
- in_margin = (delta <= k)

Decision rules:

1. If NOT in_margin:

   - if s0 > s1 → "maracuya"
   - else → "passionfruit"

2. If in_margin:
   - if max_score < amb_min_max:
     → "AMBIGUITY_LOW_EVIDENCE"
   - else:
     → "AMBIGUITY_SPLIT_EVIDENCE"

Overall frame state:

- If best detection is binary → maracuya / passionfruit
- If best detection ambiguous → ambiguous
- If no detections → no_detection

This logic must be isolated, testable, and commented.

==================================================
SENSOR MAPPING (EPISTEMIC CONTROL)
==================================================

ESP32 sends JSON packets:

{
"ts_ms": 123456,
"rubber_v": 1.23,
"fabric_v": 2.34
}

Mapping rules (MUST IMPLEMENT EXACTLY):

Rubber → margin (k):

- Rubber controls k **widely**
- Normalize rubber_v → rubber_norm ∈ [0,1]
- k = 0.02 + rubber_norm \* (0.60 - 0.02)

Fabric → evidence gate (amb_min_max):

- Fabric changes slowly over time (rotting fruit)
- Normalize fabric_v → fabric_norm ∈ [0,1]
- amb_min_max = 0.25 + fabric_norm \* (0.50 - 0.25)

Interpretation:

- Early state (fresh fruit):
  ambiguity possible with moderate evidence
- Later state (rotting fruit):
  ambiguity rarer unless model is genuinely torn
  This models epistemic decay and instability.

Optional:

- conf_floor may also drift slowly with fabric_norm
